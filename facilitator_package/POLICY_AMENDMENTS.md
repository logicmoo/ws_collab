# Facilitator Policy Amendments

1. **Sub-Agent Isolation:** Any implementation work delegated by a facilitator runs in a third, separate sub-agent context. To prevent conflicts, a facilitator must never launch a second sub-agent if one is already running. Ensure the workspace is not concurrently mutated by overlapping tasks.
2. **Parallel Facilitation:** When running in Copilot, the heartbeat automation and the CO-IDE user session are *both* facilitators operating on the same workspace. The CO-IDE naturally interleaves user chat turns with the CRON automation, so they may run simultaneously without manual locking or blocking each other. (Note: When running in Codex, this parallel Copilot-specific structure may not apply, but the single-sub-agent rule always remains in effect).
3. **Workspace Confinement & Ask Permission:** Because the facilitator *is* the CO-IDE, it operates properly without manual locking constraints for workspace navigation. However, **sub-agents must not switch workspaces**, because leaving `CO-IDE-WS` causes them to get lost. Neither the facilitator nor its sub-agents are allowed to *inspect* code or paths outside `CO-IDE-WS` without first identifying the path, explaining why, and obtaining **explicit permission**. All mutating edits, including edits made by sub-agents, must remain strictly inside the current `CO-IDE-WS`.
